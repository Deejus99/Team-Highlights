Setup / Deploy with Supabase
Supabase provides hosted Postgres, anonymous browser access controlled by Row Level Security, and realtime updates without a custom server. Use only the public anon key in this file—never put a service-role key in browser code.
  1. Create a new project at supabase.com.
  2. Open the SQL Editor and run the included table, indexes, grants and policies below.
  3. Copy the project URL and anon key into the clearly marked CONFIG object in this HTML file.
  4. Commit the single HTML file and deploy it through GitHub Pages, Vercel or Netlify.
  5. Set PUBLIC_EVENT_URL to the deployed HTTPS event URL.
  6. Reload the page, then display or download the generated QR code and test it from a second phone.

supabase/schema.sql

Prototype RLS permits validated anonymous reads, inserts and read-status updates.

create extension if not exists pgcrypto;

create table if not exists public.highlights (
  id uuid primary key default gen_random_uuid(),
  event_code text not null,
  highlight text not null,
  month integer not null check (month between 0 and 11),
  category text not null default '',
  display_name text null,
  color text not null default 'yellow',
  is_read boolean not null default false,
  created_at timestamptz not null default now(),
  constraint highlight_length check (char_length(highlight) between 1 and 280),
  constraint event_code_length check (char_length(event_code) between 1 and 80),
  constraint display_name_length check (display_name is null or char_length(display_name) <= 60),
  constraint valid_color check (color in ('yellow','pink','blue','green','purple'))
);

create index if not exists highlights_event_created_idx
  on public.highlights (event_code, created_at);
create index if not exists highlights_event_month_idx
  on public.highlights (event_code, month);

alter table public.highlights enable row level security;
grant select, insert on public.highlights to anon;
grant update (is_read) on public.highlights to anon;

create policy "anon can read event highlights"
on public.highlights for select to anon
using (event_code <> '');

create policy "anon can submit validated highlights"
on public.highlights for insert to anon
with check (
  event_code <> ''
  and char_length(highlight) between 1 and 280
  and month between 0 and 11
);

create policy "anon can update read status"
on public.highlights for update to anon
using (event_code <> '')
with check (event_code <> '');

alter publication supabase_realtime add table public.highlights;

Security note: a client-side facilitator PIN is only light protection because its value is delivered to every browser. Before production, protect facilitator updates and destructive actions with Supabase Authentication and stricter authenticated-role policies or an Edge Function.

Browser integration pattern

const client = supabase.createClient(CONFIG.SUPABASE_URL, CONFIG.SUPABASE_ANON_KEY);

// Load one event
const { data } = await client.from("highlights")
  .select("*").eq("event_code", CONFIG.EVENT_CODE)
  .order("created_at");

// Insert a submission
await client.from("highlights").insert({
  event_code: CONFIG.EVENT_CODE,
  highlight, month, category, display_name, color
});

// Realtime INSERT and UPDATE
client.channel("event-" + CONFIG.EVENT_CODE)
  .on("postgres_changes", {
    event: "*", schema: "public", table: "highlights",
    filter: `event_code=eq.${CONFIG.EVENT_CODE}`
  }, () => loadHighlights())
  .subscribe();

// Mark read
await client.from("highlights").update({ is_read: true }).eq("id", id);

From prototype to event

Implementation options

Choose based on launch speed, visual experience and the level of branding your team day needs.

A Fastest / no-code

Microsoft Forms + Excel / Power BI or Miro

Setup effort
Low; typically a few hours using existing tools.
Strengths
Familiar, secure within Microsoft 365, simple data export and reporting.
Limitations
The timeline and reveal experience require manual assembly or dashboard configuration.
B Quickest launch

Slido, Mentimeter or Padlet

Setup effort
Very low; launch a polished audience activity quickly.
Strengths
Reliable live participation, easy joining and presentation-friendly moderation.
Limitations
Limited timeline customisation, branding and layout control; licensing may apply.

Recommended: Padlet or Mentimeter when speed is the priority.

C Best fit

Custom branded web app

Setup effort
Medium; requires hosting, a shared backend, testing and moderation controls.
Strengths
Full visual timeline, live updates, custom branding, accessibility and tailored facilitation.
Limitations
Needs development ownership, data governance and production support.

Recommended when visual timeline, live updates and branding matter.

Prototype note: This demo stores data only in the current browser. Entries do not synchronise between devices. Production requires a shared backend and a deployed HTTPS URL before generating the final QR code.
